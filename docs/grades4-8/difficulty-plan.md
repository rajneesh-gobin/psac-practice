# Grades 4–8 — raising the difficulty ceiling

**Why this exists.** Parents report the questions are too easy and are getting
discouraged. That report is correct and this file is the measured version of it,
plus a sized queue so a session can pick up one batch without re-deriving the plan.

⚠ **Re-measure before starting a batch.** A second Claude session writes into this
same worktree. Every number here was true at one moment (2026-09-10) and is
regenerated by the commands in §6 — never added to by hand.

## 2. ⚠ The structural fact that decides the whole plan

**12 of the 20 Grade 4–6 packs set `noDifficulty: true`** — every English, French,
Science and History pack. `engine/app.js:6695` hides the difficulty row, and
practice is served by `getMixedQuestions()`, which draws across **all** levels at
once (`engine/questions_engine.js`).

So in those 12 packs **the mix IS the experience**. A Grade 4 English child gets a
random draw from a pool that is 94% easy, and there is no control anywhere in the
UI — for the child or the parent — to ask for something harder. Adding 50 hard
items to an 873-item pack moves the odds of meeting one from 6% to 11%. That is
why the complaint reads as "no challenge at all" rather than "not enough challenge".

**Why the flag is set is a LABEL problem, not a pedagogy one.** `PROJECT_OVERVIEW.md`
§7.1 documents it as nothing more than *"hide L1–L4 difficulty UI for this
subject"*, applied wholesale to English/French/Science/History. The real obstacle
was that **L4 is maths-shaped** — `level4Label: 'Word Problems'` is meaningless in
History. But `level4Label` is already a per-pack override, so that obstacle is
already solved and simply was never used.

⚠ Grades 7–8 packs already show the ladder (`noDifficulty` is false). Their
problem is purely stock: a "Hard" round there is served **only** from static L3/L4,
because `generateDynamic()` exists for maths packs alone. Ask grade7-science for a
Hard round today and it has 3.4 items per chapter to offer.

## 3. Two levers. Neither works alone.

- **Lever A — write L3/L4 items.** Without it, Lever B deals a Hard round of three
  questions and looks broken.
- **Lever B — surface the ladder** (drop `noDifficulty`, set a per-pack
  `level4Label`). Without it, in the 12 Grade 4–6 packs, Lever A's items are
  diluted into a mixed draw and most children never meet one.

**Order: A then B, per pack.** A pack gets its ladder switched on in the same batch
that clears its floor, never before.

---

## 4. Definition of done, per pack

1. **Every declared chapter holds ≥ 15 items at L3/L4**, so a 15-question Hard
   round deals without repeating.
2. **The pack reaches ≥ 35% L3+L4 overall**, so mixed practice climbs.
3. For a Grade 4–6 pack: `noDifficulty` removed **and** `level4Label` set to
   something true for that subject (see §5).
4. `test-exam-paper-shape.js`, `test-live-pack-content.js`,
   `test-subsection-invariant.js` and `test-option-parity.js` still pass.

⚠ **A floor is not proof of quality.** Same warning as
`docs/nce-grade9/batch_plan.md` §1: hitting 15 says how much is there, never
whether it is good.

**Total gap to the 15-per-chapter floor across Grades 4–8: 1,476 items.**

## 5. What "hard" means per subject family

⚠ **L4 is maths-shaped and does not travel.** CLAUDE.md records this as measured,
and two automatic gates were tried and rejected. Per family:

| family | L3 = | L4 = | proposed `level4Label` |
|---|---|---|---|
| Maths | multi-step within one topic | applied word problem, ≥3 operands | `Word Problems` (already set) |
| English | inference, register, ambiguity | extended passage / essay analysis | `Extended Analysis` |
| French | multi-clause grammar in context | multi-verb cloze, concordance | `Analyse de texte` |
| Science | explain a mechanism, not name it | applied scenario, predict-and-justify | `Applied Science` |
| History & Geography | cause and consequence, source use | applied scenario across two facts | `Applied Reasoning` |
| Social & Modern Studies | compare two positions | applied scenario, evaluate a claim | `Applied Reasoning` |

**The one rule that generalises.** From `docs/nce-grade9/blueprint-english.md` §7.1,
measured across five real papers and proven in this session's Grade 9 batch:

> **Nothing is examined by name.** The grammar, the rule, the law is the *means*,
> never the *object*. Ask for a repair, a judgement between two readings, or a
> prediction — never "what is the name of this?".

⚠ **Varying the numbers is not varying the question** (CLAUDE.md). A harder item
must change what the child has to *do*: withhold a quantity they must derive, ask
for an intermediate rather than the final answer, or run the problem backwards.

## 8. A separate defect that also reads as "no challenge"

The three Grade 4–6 maths packs have **no** hard-item gap, yet are still the packs
a parent is most likely to call repetitive — because the repetition is literal:

| pack | items | in a template run | biggest run |
|---|---:|---:|---:|
| grade4-maths | 762 | **240 (31%)** | ×19 |
| grade5-maths | 1431 | **439 (31%)** | ×12 |
| grade6-maths | 717 | **241 (34%)** | ×20 |

A template run is a set of stems identical once every number is replaced by `#`.
Twenty items that differ only in their numbers are **one** question to a child.

⚠ This is a **rewrite** workstream, not an *add* one, and it is not in the §7
queue. CLAUDE.md records an earlier pass that cut the `g5x` prefix to a biggest
run of 5 — these figures say the rest of the corpus was never covered. Grades 1–3
are worse still (grade3-maths ×48). Size it before scheduling it.

## 9. Risks

- ⚠ **`makeMCQ()` shuffles.** Never write an explanation naming an option position
  — `Math.random()`, unseeded, reorders on every page load. 27 such explanations
  were fixed on 2026-09-10 (commit e24a70f); the strict detector is
  `(first|second|third|fourth|last) (option|choice)`, `option [A-D]`, `answer [A-D]`.
  A loose grep over-reports this 5×.
- ⚠ **Option parity.** Harder questions grow longer options. Keep the
  within-question spread under 12 chars and never let the answer be the longest.
  `scripts/test-option-parity.js`.
- ⚠ **Subsection invariant.** Declared and tagged subsection ids must match
  exactly, per chapter. `scripts/test-subsection-invariant.js` fails the build.
- ⚠ **Exam mix shifts under you.** `examWeight` decides what an exam contains;
  adding 150 hard items to one chapter changes what every paper from that pack
  feels like. Re-run `test-exam-paper-shape.js` after every batch.
- ⚠ **Nothing reaches a child until the importer runs.**
  `netlify/functions/questions.js` reads the **database first** and only falls
  back to the built bundle, so a deploy alone changes nothing:
  `node netlify/import-questions.js`.
